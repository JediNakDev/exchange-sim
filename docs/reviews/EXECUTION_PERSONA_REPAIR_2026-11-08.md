## Concrete integration contract

OpenAPI and `web/src/lib/api/generated-schema.d.ts` define these additions. Schema generation, byte-for-byte generated-type drift, native response schema validation and focused checks below passed. Parent frontend integration remains required.

- `GET /v1/runs/{runId}/execution-trace?limit=100&cursor=...`: completed runs require native reproduction and independent replay. `verification=native_reproduction_and_replay_verified` identifies those results. New cancelled/failed terminal runs serve their actual persisted native trace with `verification=recorded_terminal_partial`; this is not a reproduction claim. Active runs return 409. Old incomplete runs without a trace sidecar return explicit evidence unavailable. Exact `items`, stable zero-based `index`, `totalCount`, `page.nextCursor`; no sampling. `kind=decision` rows describe a TWAP scheduled callback or sweep retry on delivered data. `child_report` rows describe actual delivered own reports. `simulationTimeNs` is the callback/delivery time; report `exchangeTimeNs` is distinct. `cumulativeTargetQuantity`, `knownFilledQuantity`, `parentResidualQuantity` are strategy-known shares, not inferred from absent fills. `requestedQuantity` is positive target deficit, before cap/lot rounding; `outstandingQuantity` is the known child reservation; `positionHeadroom` is host worst-case same-side headroom; `childCapQuantity` is max child size; `submittedQuantity` is actually sent (zero for a skip/reject). Nullable `childClientOrderId` links to canonical event `clientOrderId` and lifecycle. Delivered source sequence/time/touch describe only delivered market data. `reason` distinguishes child in flight, satisfied target, missing touch, no headroom/lot, submitted and host risk reject. Child reports include exchange ID, match ID, qty/leaves/cumulative qty, rejection/cancel reason. Request-only fields on report rows are zero/null and must not be charted as decisions. `finalTargetQuantity` is always the full parent. TWAP `finalTargetTimeNs` is start+(floor(duration/interval)-1)*interval, even when the run ends before that decision; sweep final target is due at start. `windowEndTimeNs` is the observation deadline, not an extra final retry. TWAP never retries after its final scheduled slice. `observationStatus` identifies full window versus run-end censoring. Old completed runs can obtain this trace by canonical native reproduction. New runs also persist `runner/execution-decisions.jsonl` through the native writer, including partial terminal decisions/reports. This optional additive sidecar is in audit exports and is compared during native verification when present. Its absence is compatible with older completed artifacts. Canonical event/ledger identity and native artifact version remain unchanged. The recorder is preallocated, included in flush accounting, and fails with recorder_overflow rather than growing/dropping evidence. Native sidecar prices are signed integer price units (1/10000 currency), times/quantities/IDs are exact decimal strings; request-only fields on child-report rows are unused zero values.
- Comparison adds `selectionPolicy`, reusable `runSelection`, `attemptLedger`. Policy without selection is most recent eligible attempt in creation order, separately per experiment and planned seed. New runs persist `creationOrdinal`, which preserves same-millisecond ordering across restart. Legacy attempts have null ordinals and retain the prior deterministic timestamp/run-ID ordering; legacy attempts precede new ordinal-bearing attempts. Seed `selectionReason` explicitly distinguishes selected, no_selected_eligible_attempt and unlaunched. Ledger includes every planned seed, including empty attempts for unlaunched seeds; every attempt has state, selected/eligible flags, reason, execution observation status/deadline/observed-through time and persisted digests. Both experiments receive identical diagnostics. Completed execution with observed full window is eligible regardless of residual; censored execution is excluded from every full-window paired metric and aligned series. Failed/noncompleted/native reproduction/replay failures are excluded explicitly. `GET /v1/comparisons?...&runSelection=<returned value>` pins those run IDs, rather than rerunning mutable most-recent selection after retries. Returned `runSelection` is an opaque canonical `r1_` compact token, not a JSON snapshot; explicit comma-separated run IDs are also accepted. The largest 512-run selection fits the native 8 KiB request-line bound. An ineligible pinned run returns 409; it never silently substitutes a retry. `none` pins an empty selection. Existing per-seed metric values retain selected run IDs; attempt digests bind canonical/ledger/manifest evidence. Ledger can grow after retries while selected paired evidence stays pinned. Coverage and request diagnostics in comparison are regenerated from the reproduced native lifecycle/metrics, rather than trusting outer summary/inspection caches.
- Neutral `betterDirection=neither`: `candidateBetterCount=0` and `candidateWorseCount=0` are N/A sentinels, not preferences or equality. `tiedCount` counts only actual exact zero differences. Parent should hide preference counts for neutral metrics.
- Run manifest adds nullable `provenance`: optional `sourceRevision`, `releaseId`, `executableSha256`. API main resolves its running executable path and supplies it through service options. The executable SHA is captured once at service startup. Source/release are explicit build metadata (`--source-revision`, `--release-id`), never guessed. New native directories also contain `provenance.json`. Empty source metadata is null. Old persisted manifests are never relabeled with the current build; missing provenance means unavailable. Reproduction is current-build artifact equivalence, not authentication of original inputs or recovery of the old executable.
- `GET /v1/runs/{runId}/audit-export`: terminal snapshot inventory, all fixed-name API/native artifacts, present/absent, exact size and SHA256. Includes native journal, complete events/lifecycle/ledger/markouts/series/config/manifests/status/summary, API state/diagnostics and inspection caches, plus provenance when available. `?artifactIndex=N&offset=B` returns up to 65536 raw bytes encoded as hex, with exact offset and nullable `nextOffset`. Inventory index, not a filesystem path, selects the file. Symbolic links are refused. Artifacts larger than 2 GiB are rejected explicitly, never truncated. Streaming file hashing keeps memory bounded. Download all present entries and verify inventory before claiming a complete package. `python3 scripts/research_audit.py download API_BASE RUN_ID NEW_DIRECTORY` supplies a local transfer utility; `verify DIRECTORY` checks integrity. Completed simulations additionally support `exsim_research verify DIRECTORY/runner`. Failed/cancelled packages preserve evidence/diagnostics but do not claim config reruns reproduce their unrecorded cancellation timing. API envelopes/wall clocks need not match a rerun.
- `summary.orders.requestDiagnostics`: separate new/cancel/replace submitted counts and exchange-rejected counts/reason counts. `arrivalTransit` gives observed sampleCount/minNs/maxNs/meanNs separately per request kind, including replacement traffic. Submitted counts are outbound requests; pre-trade host blocks remain separate risk evidence. Existing rejectedOrderCount retains new-order-only meaning. Comparison attempt ledger carries these same diagnostics. `lifecycle.replaceTransits` links exact submit/arrival positions and elapsed ns using the cancel/replace channel, plus an actual related `fillBeforeArrivalEventPosition` when observed between those events. Unknown-order alone is not called a fill race.
- Lifecycle FIFO rows now cover every rest and priority-kept replacement, with exact order ID, old exchange ID, priorityKept, current price, shares/orders ahead and level shares. A priority-losing replace removes the old order before a subsequent rest supplies its new queue; both transitions are included. At the replacement itself `queuePositionAvailable=false` and queue quantities are null because matching/re-rest has not happened yet. The subsequent rest supplies exact new-price queue quantities and carries the replacement identity. `fifoEvidenceTruncated` is explicit at 500 rows. Stages carry exchange IDs separately from the final chain summary. Selected fills preserve canonical position, exchange order and match identity.
- Markout summary adds `availableShares` (measured eligible shares). Comparison metrics add quantity-weighted `markout_per_share`, `markout_eligible_shares`, `markout_eligible_fills`, `markout_no_mark_fills`, `markout_censored_fills` per horizon. Attempt ledger includes absolute per-horizon coverage. `markout_total` and per-share values are null when no measured shares exist, separately from parent-window eligibility. Positive markout is favorable: buy future reference-exchange mid minus fill price; sell fill price minus future reference-exchange mid, weighted by measured shares. This includes initial edge and is not pure post-fill drift. Raw USD totals describe economic scale, per-share values describe conditional fill quality.
- Execution semantic errors return editable JSON pointers. Zero interval uses `/config/strategy/sliceIntervalNs` and explains greater than 0 s, integer ns minimum 1 ns. Related native parent/start/duration/offset/slice-count checks map to their execution fields without a broad parser refactor.
