## Result

- Breadcrumb ancestors are clickable, including Run analysis from inspection
  and Source study from a variant. Run links preserve the comparison cohort.
  The current location remains a noninteractive breadcrumb. Narrow headers use
  local scrolling rather than increasing document width.
- New study exposes the built-in model immediately under task selection:
  TWAP, immediate sweep, fixed-spread MM or inventory-aware MM, gated by actual
  service capabilities. A direct parameter link focuses the selected strategy's
  parameter group. Autogenerated study names follow a changed task; custom names
  and variant lineage remain intact.
- Research and New study link to External clients. That page exposes OUCH 4.2
  over SoupBinTCP, FIX 4.4 and SBE 1.0 over FIXP, endpoint/session identity,
  ITCH/MoldUDP64 delivery/retransmission settings, strategy name and parameter
  JSON. Suggested ports follow the repository example; explicit ports survive
  protocol changes. FIX exposes SenderCompID and TargetCompID.
- Export is a local client settings handoff, not a native configuration file.
  It preserves JSON parameters verbatim as parametersJson, excludes credentials,
  validates syntax and input bounds, and focuses the first invalid field.
  No server settings are applied and no code is uploaded or run.
- Native server mapping and startup instructions accompany the form. The
  repository example supplies instrument rules, a continuous SPY instrument,
  and background maker/taker bots. The bundled exsim_client is correctly labeled
  OUCH-only. Native FIX and FIXP clients are separately supplied by the user.
- Telemetry copy no longer concludes that a separately launched server is down
  from an unattached research API. Empty telemetry uses readable next actions.

## Actual boundary

The browser does not yet launch or control the protocol server, execute an
external strategy, bridge its live telemetry, or turn external sessions into
paired-seed research results. The exported reference is explicitly not consumed
by exsim_server or exsim_client. Those integrations require separate native API
and runtime work; the UI does not claim them. No end-to-end external-client
session, native build, screen-reader or human first-use evaluation was performed
in this frontend amendment.
