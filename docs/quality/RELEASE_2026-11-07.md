verified API/frontend pair. This release includes TWAP/sweep configuration and
parent metrics, recoverable experiment creation, durable mutation reservations,
recorder-failure containment, bounded cache reads and the selected-fill identity
repair. It does not claim exhaustive correctness or implement the deferred
product capabilities listed below.

## Packaging and restoration

The immutable release is under
`$HOME/Library/Application Support/exsim/releases/production-20261107-8ee86f1/`.
It was first copied as a candidate, verified against its 1,830-entry manifest,
and privately booted from its own files. Direct/proxied service identity, all
four research strategy capabilities, HTML, exact static-asset bytes and a TWAP
preview passed. The verified candidate was then renamed to the production path;
its bytes and manifest remained unchanged.

The maintenance procedure blocked frontend ingress, confirmed there were no
active simulations, unloaded both LaunchAgents and checked for another API
writer using the data directory. A full offline backup was published and
verified, then restored to a separate private directory. No live-file copy was
treated as a consistent backup. Eleven existing completed runs were preserved.

The new copied pair loaded that restored data. All **84** saved experiment,
run, summary, manifest and first-page/series inspection responses matched their
old-service responses exactly. A fresh native paired comparison preserved its
original **22** metrics and every other field. The new execution API adds
exactly seven metric rows, each unavailable with zero samples for these older
market-making runs. Those additions were checked explicitly, not ignored as
arbitrary differences. Previewing execution still creates no experiment/run.

Before the final handoff, both old services were stopped again, quiescence was
rechecked, and the entire production data inventory matched the offline backup
byte for byte. The old immutable releases and original plists are retained.
After selection, both new supervisors are running with the intended absolute
executables and working directories. API7600 and frontend3760 listen only on
127.0.0.1. Local readiness and the existing private Tailscale Serve endpoint
both pass; other Serve handlers were unchanged. This host's private URL is
delivered to the user separately, not embedded in public assets.

An initial maintenance attempt checked `launchctl` unload completion too soon;
it aborted before backup and restored the old pair. The corrected procedure
waited for unload completion. The first restored-response comparison also
stopped on the seven additive metric rows and restored the old pair. Only after
checking the exact additions did the final preflight pass. Original data bytes
were checked again before promotion; neither interrupted attempt justified
silently discarding a mismatch.

## Remaining boundaries

The service has one writer, no separate multi-user authorization, no arbitrary
uploaded strategies and no reconstruction of a lost live simulation. Synthetic
agents are not calibrated market impact; historical counterfactual strategy
replay and hostile deterministic scenarios remain future work. Protocol mode is
a separate process and is not monitored by the research UI.

Per-key mutation reservations provide at-most-once behavior, not automatic
resolution of uncertain outcomes. There is no multi-file power-loss transaction.
An incomplete terminal cache set can prevent startup and require operator
recovery. The 256 MiB bound is per inspection cache, not a total-process memory
budget. Independent coverage limits are preserved in the review reports.

New demonstration runs after promotion use the new idempotency store. An old
JSONL-only binary must not write that current data directory. Use a compatible
reader or an explicitly selected offline data restore that preserves later data
and acknowledges any work it would discard. No automated writable downgrade
was performed. [Operations and rollback](../DEPLOYMENT.md).
