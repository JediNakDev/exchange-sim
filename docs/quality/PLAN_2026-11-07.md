# Product completion and quality plan

The user rejected treating the redesigned demo as a completed product and asked for a thorough, delegated implementation and review pass. This plan is the shared acceptance checklist. A checked item requires integrated behavior and evidence, not just a branch, declaration, or launch.

## Delivery order and ownership

1. Parent: make the existing experiment workflow recoverable. Fix partial seed launches, lost-response retries, full experiment/run pagination, paged fill/order inspection, explicit failures, variant lineage, and access to inventory-aware quoting. These repairs are integrated with focused and browser regressions; the selected-fill identity repair now has independent clearance.
2. Durability child: audit and repair API mutation persistence, idempotency and restart behavior with real temporary-directory failure/restart tests. Own persistence/reload/idempotency portions of the service, not its strategy catalogue.
3. Execution child: expose the existing C++ TWAP and immediate-sweep research strategies through the HTTP contract, with parent-order metrics, discovery, native reproduction, and focused integration tests. Parent integrates its schema changes and implements the browser workflow afterward. Own strategy/capability/metric portions of the API, not persistence.
4. Delivery child: production packaging, readiness, consistent backup/restore and rollback tools, tested only in disposable directories. Never stop or modify the current deployment during the audit.
5. Parent: integrate completed commits serially, resolve contract conflicts, run focused integrated checks, add execution UI, then commission independent review of the integrated changes. Review is a new task; implementation reports are not independent review.
6. Parent: deploy a validated copied release with rollback and backup, publish accurate docs and evidence, and push only the integrated result. Preserve current live services until a concrete replacement passes checks.

All children use GPT with xhigh reasoning in harness-created isolated worktrees, based on the dependent exchange-simulator commit 6d5c29f. No Ollama, extra child delegates, parallel heavy gates, new comparative benchmarks, or main-branch merge. Compile jobs are capped at two per child; full suites, sanitizers and Docker need a serial integration slot. Parent frontend work is absent from child checkouts.

## Acceptance checklist

### Trader workflow

- [x] Experiment creation reports save and seed-launch outcomes separately.
- [x] A partial launch can continue without losing completed work or silently replacing failed runs.
- [x] A lost mutation response can be retried with the same immutable request/key.
- [x] Variants copy the actual saved config and record their lineage.
- [x] Fixed-spread and inventory-aware market-making can both be configured in the browser.
- [x] Parent-order execution has an end-to-end UI/API/runner path, with TWAP versus immediate execution and explicit residual quantity, completion and costs.
- [x] Experiment lists, selectors and run lists do not silently truncate at a first-page limit.
- [x] Every fill and own order is reachable through bounded paging; selection and run-navigation state remain correct.
- [x] Empty, loading, offline, malformed-error and changed-run-state views provide a recovery action.
- [x] Exact money, quantities, seeds, IDs and timestamps remain strings throughout the frontend.

### Research trust and correctness

- [x] Restart and I/O-failure checks prove the documented persistence and idempotency behavior.
- [x] New execution kinds retain canonical API/CLI identity, native reproduction checks, causality and independent per-run state.
- [x] Execution metrics reconcile to native runner fills/accounting and explicitly represent unavailable benchmarks.
- [x] Paired comparisons expose changed assumptions, seed counts and unavailable/censored observations.
- [x] An independent review of the final integrated changes has no unresolved high-severity finding.
- [x] Historical reconstruction, synthetic strategies and protocol sessions are labeled accurately; unsupported realism is never implied.

### Runtime, operations and delivery

- [x] Existing bounded journal, protocol recovery, allocation and sanitizer evidence is mapped to exact revisions; changed code gets relevant fresh checks.
- [x] Mutation proxy rejects cross-site form requests, bounds request bodies, has an upstream deadline and renders structured errors after broken responses.
- [x] Packaged releases have explicit source/build identity, complete self-hosted assets and readiness checks.
- [x] Consistent backup/restore and rollback are demonstrated with isolated fixtures, not claimed from copying active files.
- [x] Production remains loopback plus private Tailscale; public multi-user hosting is not claimed.
- [x] Frontend checks and targeted failure/interaction regressions are reproducible from the repository.
- [x] Test gates are scoped by risk and cost; no repeated full suites or measurements without new evidence needs.
- [x] Final docs distinguish completed behavior, independently verified behavior and deferred capabilities.
